# Project Start

Use this skill when a new software project needs a durable working frame before implementation.

## Workflow

1. Confirm the objective, users, done criteria, non-goals, constraints, and portability requirements.
2. Inspect the destination and stop on ambiguous ownership or an existing unrelated project.
3. Write the smallest requirements and technical design that resolve consequential decisions.
4. Define checks that can run locally with synthetic fixtures and no credentials.
5. Create a current task that maps each implementation step to evidence.
6. Implement only after the work contract is coherent, then run the declared checks.

Do not invent deployment, integrations, or extensibility that the objective does not require. Preserve existing files unless the operator explicitly assigns them to the project frame.
